# Compact controls, native targets and empty rows

Cycle 25 studies the document library's enlarged view selector and the scanner's checkbox findings before adding the page to the maintained layout matrix.

## GOV.UK source review

Reviewed GOV.UK Frontend at revision `dacc29dd045c8c3e2d7245616215da6515b8b5ab`. The select [entry point](https://github.com/alphagov/govuk-frontend/blob/dacc29dd045c8c3e2d7245616215da6515b8b5ab/packages/govuk-frontend/src/govuk/components/select/_index.scss) imports a [style mixin](https://github.com/alphagov/govuk-frontend/blob/dacc29dd045c8c3e2d7245616215da6515b8b5ab/packages/govuk-frontend/src/govuk/components/select/_mixin.scss). That mixin bounds the control with `max-width:100%` and explains its minimum width in relation to narrow screens. The local example also needs to consider its actual text at enlarged sizes. A bounded box alone can truncate a selected value.

The [select guide](https://design-system.service.gov.uk/components/select/) discusses choosing another control when a public-facing service can present fewer options. That recommendation has a particular service context. The library retains its compact native toolbar selector. Its visible label becomes "Show documents" and the two choices become "Active" and "Archived". Together they preserve the original meaning and fit at the tested size.

The checkbox [entry point](https://github.com/alphagov/govuk-frontend/blob/dacc29dd045c8c3e2d7245616215da6515b8b5ab/packages/govuk-frontend/src/govuk/components/checkboxes/_index.scss) imports its own [style mixin](https://github.com/alphagov/govuk-frontend/blob/dacc29dd045c8c3e2d7245616215da6515b8b5ab/packages/govuk-frontend/src/govuk/components/checkboxes/_mixin.scss). The source keeps a 44px input for its smaller checkbox and paints a 24px square through the label. It also provides focus and forced-colour outlines. The [checkbox guide](https://design-system.service.gov.uk/components/checkboxes/) describes smaller marks on information-dense screens used repeatedly.

The local library already had 44px clickable labels around its 18px inputs. Those painted-input measurements were candidates, not proof that the actual activation area failed. The new implementation keeps the native input itself at 44px and paints the compact mark inside it. Pointer padding now hits the input directly. The existing label, native checked state and keyboard operation remain intact. This transfers the separation of mark and target without adopting GOV.UK's colours, dimensions for all controls, Sass tooling or service rules.

## Native activation and visual checks

[WCAG's target-size explanation](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) concerns pointer targets and includes size and spacing alternatives. The local 44px choice is larger than the minimum size. The [HTML label specification](https://html.spec.whatwg.org/multipage/forms.html#the-label-element) defines control association while allowing platform differences in activation. The tests therefore observe actual input hits and activation rather than treating label geometry as proof of behavior.

The maintained pointer sequence clicks or taps inside native input padding, outside the painted square, for all eight rows. It checks selection and clearing after each activation. Keyboard arrows follow the current visible order. A deliberate pointer-events mutation makes the geometry remain large while activation is unavailable; the checker rejects the hit on the table cell. Actual physical devices remain unverified.

The visual scanner now excludes the completely clipped semantic header from contrast and clipping measurements. It separately rejects controls that retain tab stops inside that clipping. A fixture preserves an ordinary accidentally clipped paragraph finding, then restores a hidden button's tab stop and expects a failure. This does not treat partial clipping or arbitrary clip paths as invisible. A [separate reproduction](../cycles/25/before/opacity-focus.json) found that the initial guard incorrectly flagged an opacity-zero native input whose visible label had a 2px keyboard ring. GOV.UK uses transparent inputs with visible label painting too. The corrected guard measures fully clipped tab stops, and a fixture retains the label-based focus pattern. Opacity alone does not establish that keyboard focus is invisible.

## An empty state missed by the first matrix

Visual review of the first enlarged empty capture found text occupying only the 52px checkbox column of a 288px row. The first-cell selector overrode the less-specific empty-state grid span. The normal scanner did not report viewport overflow because the text still stayed within the page.

The empty cell now spans the row and uses the available width. A domain check measures its width against the table body. A deliberate grid-column mutation must fail that check. The matrix includes both an initially empty archive and the empty active view after archiving every document, alongside active, partially selected, archived, selected archive and restored states.

WebKit abbreviates September as "Sep" while the other observed engines use "Sept". The date checker normalizes that one valid abbreviation difference and still compares the independent expected day, month and year. It does not format its expected dates by calling the renderer's formatter. Owner, title, format, status, visible rows, selection, action text and messages have independently specified expectations too.
