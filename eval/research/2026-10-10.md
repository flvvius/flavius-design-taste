# Chart semantics and forced-colour rendering

Cycle 21 revisits the usage chart after the maintained suite gained multiple browser engines. The earlier chart review covered narrow labels and a common scale. It did not establish that the series remained visible after browser colour substitution.

## Observable Plot

Reviewed [`src/plot.js` at `535723d5e433727720d9b673c31622821bb03210`](https://github.com/observablehq/plot/blob/535723d5e433727720d9b673c31622821bb03210/src/plot.js), retrieved through GitHub's contents API on 10 October 2026. The root SVG accepts a label and description. Titles, subtitles, legends and captions can produce a surrounding HTML figure with semantic headings and a figcaption. The [published accessibility guide](https://observablehq.github.io/plot/features/accessibility) also distinguishes descriptive marks from redundant marks hidden from the accessibility tree.

The useful lesson is that a plot needs both graphic semantics and readable context outside its drawing. The usage example already has a named figure, a chart description, a prose summary and an exact-value table. Keep those pieces together when testing period changes. Importing Plot would add a dependency without fixing the observed CSS fills; this cycle retains the standalone HTML example.

## Primary standards and observed behavior

The [CSS colour adjustment specification](https://www.w3.org/TR/css-color-adjust-1/#forced-colors-properties) describes forced colour replacement and suppression of non-URL background images. That makes a gradient an unreliable series identifier unless it receives explicit treatment. The [non-text contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) addresses graphics needed to understand content, including chart marks.

The [baseline measurements](../cycles/21/before/marks.json) show actual colour replacement in Chromium and Firefox. Their selected bars became white on white, and previous-series gradients became `none`. The WebKit build matched the media query without replacing the palette. Its ordinary render does not refute the failure in the other engines.

The correction uses CanvasText and Canvas for the marks and legend. Only those small graphics opt out of automatic adjustment to preserve their solid and striped distinction. Controls and surrounding text keep automatic adjustment. The shared chart reference now asks for this check without requiring a browser library or repository script.

## Scope of the evidence

The maintained check compares known period values with the rendered totals, table and accessible description. It measures each bar against the available value-axis extent and checks the common baseline. It measures solid-fill and striped-border contrast against their adjacent backgrounds, then checks that the stripe image remains present. Screenshots require separate review of the actual pattern and composition. Deliberately erased patterns and misleading scales verify that the checker rejects those defects.

This is self-review. Browser emulation is not evidence for every operating-system contrast theme, a physical device or a screen reader. WebKit's unavailable palette substitution remains explicitly unverified. The earlier seven-repository comparison remains in [the preceding research notes](2026-10-09.md); this study adds one chart repository rather than replacing those findings.
