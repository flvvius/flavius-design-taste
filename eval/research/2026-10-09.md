# Design research, 9 October 2026

This pass studies how other projects teach design decisions and how designers check their work. It is a selective comparison, not a ranking of all design repositories. Repository revisions and inspected files are recorded in [sources.json](sources.json). No external skill is installed as a dependency and no third-party instructions replace this repository's direction.

## Designers and working components

[Rauno Freiberg's interaction essay](https://rauno.me/craft/interaction-design) treats the time between intention and response as part of design. Its examples are useful prompts for checking pointer travel and interruptions, rather than reasons to add effects everywhere. This repo should check repeated activation, keyboard destinations and hover behavior on touch. His [craft collection](https://rauno.me/craft) also demonstrates that native and browser experiments need evidence from their own platform.

[Emil Kowalski's animation article](https://emilkowal.ski/ui/good-vs-great-animations) explains origin, easing and reviewing motion slowly. Adopt purposeful feedback, explicit animated properties and checks under interruption. Keep Editorial calm's restrained timing and Personal room's optional drawn marks. A gesture, a frequent command and an occasional illustration do not need identical motion rules. [Sonner](https://github.com/emilkowalski/sonner) is a concrete component reference, not a dependency or a demand to use toasts.

[Paco Coursey's redesign account](https://paco.me/writing/redesign-2021) is useful for its willingness to simplify a personal site. His [cmdk repository](https://github.com/dip/cmdk) documents keyboard behavior, composition and accessibility concerns alongside styling. This repo should make behavior inspectable without insisting on a particular React component.

[Maggie Appleton's digital-garden essay](https://maggieappleton.com/garden-history) makes room for personal, evolving work and mixed media. Personal room can support notes and collections, with relationships in the content rather than a forced marketing sequence. This is a reason to build a reading-oriented transfer example, not to add garden imagery to every page.

[Frank Chimero's The Web's Grain](https://frankchimero.com/blog/2015/the-webs-grain/) argues for working with the medium's fluid, vertical nature. Let text determine layout and collapse illustrated arrangements before they become brittle. Keep native links, ordinary scrolling and readable fallbacks. A photograph and a paragraph scale differently; a fixed desktop composition cannot be the mobile contract.

## Standards that settle measurable questions

- [WCAG reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) motivates a 320 CSS pixel check. It is separate from text enlargement and has exceptions for content that requires two dimensions.
- [Resize text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html) motivates a 200% text check. Doubling the root size alone misses explicit pixel-sized labels. Snapshot all computed text sizes before changing them so inheritance does not multiply the scale twice.
- [Text spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html) requires content to survive user overrides. Test 1.5 line height, 2em paragraph spacing, .12em tracking and .16em word spacing together. These are test values, not the taste's new defaults.
- [Focus not obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html) prompts checking where activation leaves keyboard users. A visible outline in CSS does not prove focus landed on a visible control.
- [Minimum target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) distinguishes the 24px criterion and its exceptions from this repo's preferred 44px standalone touch targets. Inline links should not be padded into giant buttons.
- [Disclosure guidance](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/) supports ordinary show/hide controls. Retain native details/summary behavior rather than inventing a room-specific widget.
- [Agent Skills specification](https://agentskills.io/specification) supports short entrypoints and relative supporting files. An installed taste folder must not need the original repository or a paid API.
- [Design Tokens Format Module](https://www.designtokens.org/tr/2025.10/format/) offers an exchange format. The current JSON is a custom portable format, not DTCG. An export needs explicit handling for fluid CSS expressions and verification in a real consumer before claiming interoperability.

## Findings before improvement

The ten existing cycles cover Editorial calm, including useful interaction and native evidence. Personal room had only a portfolio specimen and temporary browser verification. Its root-font test missed fixed-size labels. A stricter baseline retained in cycle 11 found 357px page width in a 320px viewport when all text doubled. Activating the same project twice left its disclosure closed. Both are concrete failures despite passing package checks.

The next passes should first repair those failures and make their checks repeatable, then test a practical reading/editing screen with Personal room. Keep source decisions, visual critique and automated checks distinct. A passing browser script cannot measure whether a composition says anything about its owner, and one author's self-review is not an independent agent evaluation.

## Forced-colour follow-up

[MDN's forced-colours reference](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/forced-colors) describes how the browser replaces author colours and removes shadows. Preserve that user choice. Selection must survive with an underline, glyph or other structural marker. Cycle 14 found that selected and unselected palette buttons had the same border after substitution, then checked keyboard switching and form boundaries in Chromium's emulation. This is browser evidence, not a Windows device test.

## Native type follow-up

Apple's [Dynamic Type session](https://developer.apple.com/videos/play/wwdc2024/10074/) shows text and its layout growing together, with scrolling when the content exceeds the display. Its [UIKit text adjustment reference](https://developer.apple.com/documentation/uikit/uicontentsizecategoryadjusting/adjustsfontforcontentsizecategory) requires preferred semantic fonts or `UIFontMetrics` for automatic changes. The [custom SwiftUI font guide](https://developer.apple.com/documentation/swiftui/applying-custom-fonts-to-text) maps a custom face to a semantic text style through `relativeTo`. Cycle 15 uses an iOS simulator, scales Schoolbell through UIKit metrics, and separates fresh-launch layout evidence from live updates. Native dimensions need platform mapping; the portable JSON's browser expressions are not native point values.

## Native interaction follow-up

Apple's [accessibility audit guide](https://developer.apple.com/documentation/accessibility/performing-accessibility-audits-for-your-app) distinguishes common automated findings from a fully accessible application. [XCUIAutomation](https://developer.apple.com/documentation/xcuiautomation) supports user-interface actions and state inspection. Cycle 16 uses XCTest swipes and taps rather than dispatching control events inside the app, and calls the unfiltered audit at three reading positions. Its baseline found state leaking between notes and an off-screen destination at the largest text size, despite the earlier layout pass. Those are navigation and ownership defects, not palette defects.

## Missing-font follow-up

Apple's [font overview](https://developer.apple.com/documentation/technologyoverviews/fonts) asks apps to verify font availability and provide a fallback when a font is missing or changed. The [named UIKit font initializer](https://developer.apple.com/documentation/uikit/uifont/init%28name%3Asize%3A%29) is optional. Cycle 17 removes the actual font resource and its registration from the app bundle. The native specimen's force-unwrap crashed in that build. A scaled system face preserves the reading path; the regular build still verifies Schoolbell rather than accepting a silent packaging fallback.
