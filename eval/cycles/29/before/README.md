# Exploratory native baseline

The original cycle 10 SwiftUI view was compiled with its captured sRGB tokens and the retained ScrollView host. Eight simulator captures cover light/dark appearance, normal/accessibility XXXL text, and top/bottom positions. The [host record](native-host.json) confirms a 375-point viewport and the selected system category, with the body font changing from 17 to 53 points. This is rendering evidence. It does not establish control interaction, text geometry, VoiceOver or physical-device behavior, and no completed cycle 29 review is claimed.

The source study inspected CVS Health's [Dynamic Type implementation](https://github.com/cvs-health/ios-swiftui-accessibility-techniques/blob/563e762a3999f3e37395f88c6cdb2b13f0b37488/iOSswiftUIa11yTechniques/iOSswiftUIa11yTechniques/DynamicTypeView.swift) and [documentation](https://github.com/cvs-health/ios-swiftui-accessibility-techniques/blob/563e762a3999f3e37395f88c6cdb2b13f0b37488/iOSswiftUIa11yTechniques/Documentation/DynamicType.md). Its explicit good/bad comparisons distinguish scalable type from truncating labels and fixed horizontal layouts. It also caps large headings; that tradeoff was not adopted here. Apple's [Dynamic Type session](https://developer.apple.com/videos/play/wwdc2024/10074/) connects text scaling with layout adaptation and actual platform inspection. These sources identify questions for a future native review, rather than prove a defect in this baseline.
