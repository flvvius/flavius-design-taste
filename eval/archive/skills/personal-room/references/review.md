# Choose, build, critique

## Decide before drawing

Name the subject, the visitor and the next useful action. For an existing page, inspect its content and behavior before proposing a new setting. Preserve the user's references, brand assets and factual copy. If the task leaves room for a choice, compare two plausible compositions briefly and choose the one that helps the content most. A small edit does not need a new design presentation.

Decide how this screen will be used. A collection can invite exploration. An article needs a reading measure and upright text. A tool needs predictable controls and immediate feedback. The same project can have all three. Carry the palette and title voice across them, then adapt density and expression to the task.

Before implementation, write down the chosen palette, type roles, composition, main visual gesture and what will become simpler on a phone. Give each choice a reason tied to the subject. This can be a short paragraph. If every reason is an aesthetic adjective, return to the content.

## Keep the identity while adapting it

The recognisable hand, restrained accent marks and personal voice matter more than a literal illustrated room. Objects, photography, notes and fluid composition are flexible tools. A shelf of projects, a bar-shaped resume or a centred night poster is one solution, not the taste's compulsory anatomy.

| Situation | Keep | Adapt |
| --- | --- | --- |
| A personal collection | Handwritten title, a useful object or image, visible item names | Let the collection determine grid, list or sequence. |
| A long note | Title voice, paper or navy palette, honest author details | Use a readable face for extended prose and keep paragraphs left aligned. |
| A practical form | Personal title and a restrained mark | Use upright labels, conventional fields and precise errors. |
| A different script | Palette, hierarchy, line treatment | Use a face that covers the language; do not mix missing handwriting glyphs into every word. |
| A small screen | All useful content and actions | Flatten the scene before reducing text size. |

## Inspect before measuring

Look at the opening and one supporting section without the test report. Is the subject apparent? Does the main gesture draw attention to meaningful content? Can a visitor find the work, read it and act without deciphering the metaphor? Compare paper and night where both are offered. A colour change alone is not a second composition.

Check that handwritten labels are large enough, that asides do not compete with the main copy, and that decorative marks do not look like clickable controls. Remove an unrelated prop before adding another effect. Look at a normal phone view as well as the stress captures.

Then inspect the technical evidence. Test 320px reflow, every text role at 200%, user text-spacing overrides, keyboard activation and focus destinations, reduced motion, missing fonts and no script. Check the actual rendered backgrounds, not just palette pairs. Test the same action twice, including closing and reopening a disclosure with the same URL hash. Returning to the same destination is still an action.

Gate pointer hover movement to devices that support hover. Keyboard focus can use colour and an outline without borrowing the object's pointer animation. Keep essential names visible on touch.

## Record a useful finding

A finding names the affected screen, the trigger, what happened and why it interferes with the visitor's task. Distinguish a broken action from a readability problem and a visual preference. Fix observable failures first; refine composition where the brief supports the change.

After a correction, rerun the affected scenario and inspect its render. Report what was verified, what failed and what remains unverified. A synthetic browser test is useful evidence for browser behavior, not certification of native apps, screen readers or design quality. Self-review is not an independent assessment.
