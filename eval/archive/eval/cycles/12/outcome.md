# Cycle 12: Personal room on a practical screen

The original Personal room example taught an illustrated personal collection. This pass asks whether the same taste can support reading and editing without reproducing a room full of props.

The [repair notebook](index.html) uses a fictional bookbinder's notes. A handwritten opening and a single thread mark establish its voice. Prose, dates, navigation and form fields use the system reading face. The paper and night palettes stay recognisable; neither needs an extra scene. A Romanian sentence stays in the reading face so unsupported Schoolbell glyphs do not interrupt a word.

Notes have native disclosure controls and ordinary hash links. JavaScript adds selection, editing, validation and local browser saving. Failed storage preserves the draft, including a move to another note and back. Cancel leaves saved content alone. Without JavaScript, the notes remain readable as disclosures and editing controls stay hidden.

[Browser evidence](after/checks.json) covers this notebook with the two existing specimens. Its 36 layout reports include narrow, medium and wide screens, doubled text and spacing overrides in both themes. Tests also cover keyboard navigation, validation focus, cancel, save/reload, failed-storage drafts and no-script reading.

The root agent reviewed desktop paper and mobile night renders, then corrected screenshot capture to return to the top before a full-page image. Capturing a scrolled viewport had painted the offscreen fixed skip link into the middle of the image. This was a capture defect, not a visitor-visible link state. The review is explicitly self-review.

The new decision guide teaches how to retain the title voice while adapting expression to reading and task work. Editorial calm's review guide now also separates the user's task, visual judgment and measured evidence. Both installed skills remain independent folders.
