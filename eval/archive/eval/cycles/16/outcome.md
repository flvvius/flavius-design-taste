# Cycle 16: Native navigation through the visible controls

Cycle 15 measured text and targets, changed Dynamic Type live, and dispatched control events inside the app. Those checks did not establish how a reader reaches and uses the controls. This cycle runs XCTest swipes and taps with ordinary native animations, then calls Apple's unfiltered accessibility audit at the opening, action area and next-note heading.

The baseline used the native source at commit `45a7f87`. Its [standard-size result](baseline-standard.json) found repaired state leaking into the next note. Its [largest-size result](baseline-largest.json) found the next-note heading outside the viewport after activation. The [test source](baseline-tests.swift) and [source hashes](baseline-sources.json) identify the original checks. The accessibility audits had passed before the behavioral assertions failed. That distinction matters: a native audit can pass while navigation or state ownership is wrong.

The revised native specimen stores repaired state with the note. Switching notes updates the heading, paragraphs, date, action text and selected state together. After layout, it brings the new heading into view and posts a native screen-change notification naming that heading. The UI test also returns to the first note and verifies that its own repaired state survives the round trip.

[After-checks](after/checks.json) retain the four XCTest results, across paper and night at ordinary and largest accessibility text. Each case exercises scrolling, marking, moving to the next note and returning. Three unfiltered audits per case make twelve audit calls. None are skipped or suppressed. The captures were attached by XCTest after interaction, with native animations enabled. They are taken before auditing the destination because the audit can change the viewport during its checks. Visual inspection caught that capture-order error in the first pass. The [layout regression checks](after/layout-checks.json) also pass nine layouts, two live size changes and three dispatched control events against the corrected source.

This is self-review by the root agent. The images show the next heading visible at the destination, with native reading text and the handwritten section title. The shared native and pattern guidance now explains item-owned state and navigation after enlarged layouts. No palette or dimension token changed; these findings concerned behavior.

Run `npm run check:native-ui -- --output .artifacts/native-ui` on macOS with Xcode and an installed iOS runtime. Use a fresh output directory because Xcode result bundles cannot be overwritten. The runner builds a temporary project without an additional project generator dependency. The default isolated-simulator run also passed, and [cleanup verification](after/cleanup.json) confirms that its test device was removed. It creates and removes an isolated simulator by default, and saves complete logs, result bundles, attachments and source hashes. An optional `--device` accepts a dedicated test simulator and changes its text-size and appearance settings.

These are simulator gestures and automated accessibility audits. They do not prove physical-device behavior, hardware keyboard operation or VoiceOver reading order. Posting a focus notification is not evidence that VoiceOver handled it correctly. Apple's [audit guidance](https://developer.apple.com/documentation/accessibility/performing-accessibility-audits-for-your-app) also distinguishes automated findings from full accessibility.
