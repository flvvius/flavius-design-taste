# Focus when responsive controls change

Cycle 24 reviews the document library after the chart and article search received maintained state checks. Its original review fixed hidden header controls in the narrow tab sequence. The new reproduction examines a control that already has focus when the viewport crosses the breakpoint.

## Persistence and visibility

[W3C's keyboard interface guidance](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/) distinguishes visible, persistent focus from selection. Removing or hiding a focused element requires a logical destination. The [Focus Visible explanation](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html) describes why keyboard users must be able to identify the active control. These principles apply to responsive replacements as well as dialogs and deleted rows.

The [baseline captures](../cycles/24/before/chromium.json) record the same two failures in Chromium, Firefox and WebKit at commit `7e184b4a847576906e2cb36e8bf2e90680aaa349`. Shrinking keeps focus in the clipped table header. Widening drops mobile sort, direction or select-all focus to the body. The original handler changes tab indices but supplies no replacement focus.

The baseline's `visible` field records `Element.checkVisibility()`, which returns true for the clipped header control. Its `headerClip` field and screenshot reveal the clipping. That API alone does not prove a focus indicator is visible. The maintained checker additionally rejects clip paths on the focused element's ancestry, checks viewport geometry and measures the outline.

## Transferring focus without changing state

A disappearing select-all checkbox maps to the checkbox in the other layout. A disappearing sort header maps to the mobile sort selector. Returning from the mobile sort selector or direction button focuses the header for the current sort key. Focus movement does not select documents, change sorting or rerender rows.

CSS can blur a hidden mobile control before the media-query callback examines `document.activeElement`. The example remembers a focused mobile control through that disappearance. An ordinary blur while the control is visible clears the record. The responsive handler uses the remembered control only when focus has fallen to the body, and only to transfer to its visible equivalent. Explicit blur and focus on a row or view selector remain undisturbed.

The regression fixtures remove the focus transfer and, separately, the reverse sort transfer. Each must fail at its specific missing destination. They do not depend on every engine delivering blur and media events in the same order. Keyboard activation after resizing and a changed sort key check that the destination still operates the current state.

## Follow-up source comparison

Reviewed Radix Primitives at revision `01259a024d82ab3892d1e5938b1a50bb352c6df5` after implementing the local transfer. Its [philosophy](https://github.com/radix-ui/primitives/blob/01259a024d82ab3892d1e5938b1a50bb352c6df5/philosophy.md) separates semantic behavior from presentational styling and calls for app-context guidance alongside component tests. That distinction fits a portable taste: visual rules must preserve the host control's behavior.

The [focus-scope source](https://github.com/radix-ui/primitives/blob/01259a024d82ab3892d1e5938b1a50bb352c6df5/packages/react/focus-scope/src/focus-scope.tsx) keeps a last-focused element for trapped scopes. It ignores focus-out events with a null destination, and separately observes removal when focus falls to the body. Its comments distinguish removal from switching browser windows. These mechanisms reinforce the need to identify the cause of lost focus. They do not supply a responsive replacement map.

The local library stays freely navigable. Its transfer runs at the breakpoint and affects only the disappearing control. Radix's scope trapping, mutation observer and React dependencies are not copied into the example or the shared skill.

## Coverage boundaries

The default maintained browser run adds library focus and archive-history checks in both themes. It retains focused-control geometry, outline and state observations, plus narrow screenshots. Sorting, partial selection, select-all, archive, restore, empty archive and undo have independently specified expected rows and messages.

These are interaction checks at ordinary text sizes, not a full layout matrix for the library. Its native table and stacked narrow view still need enlarged-text, spacing, forced-colour and assistive-technology review. The shared web guide records the portable focus rule without requiring this table, its breakpoints or the repository's test tools.
