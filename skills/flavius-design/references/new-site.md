# Start a site

Fill the brief with audience, primary action, message, constraints, content inventory, proof and known unknowns. Mark placeholder copy. Do not create impressive metrics, testimonials or customer logos as invented evidence.

Arrange the pages and section order before choosing effects. The structure should answer what this is, whom it helps, why it is credible and what the visitor can do next.

Prepare two small genuinely different compositions in code or a sketch. Change hierarchy, reading order, alignment or the relationship between text and a meaningful object. A new color on the same hero is not another composition. Explain each in terms of the subject.

Choose the direction, type roles, density and one memorable idea. A service that ships code could show an annotated before/after or a reviewable change. A portfolio can use objects from its owner. Do not choose a shelf simply because Personal room has one.

Build one complete representative page with real responsive structure, working actions and truthful states. Then extend to remaining pages. Keep content inventory and route names consistent. The starter is optional. Adapt the existing stack when the project already has one.

Review mobile as a composition, not a squeezed desktop. Check headings, measure, long content, keyboard navigation, contrast, focus, 200% text, missing imagery and reduced motion. Verify links and any form's validation and success/failure behavior. A fake form that reports Sent without transport must be labelled a prototype, or use an ordinary contact destination.
